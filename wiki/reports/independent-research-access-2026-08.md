### A2. Anthropic Insights (web page and appendix)

7. **Anthropic Insights, the one-line definition and the rename** (*Lead ¶3*, extracted from definition 2 for the record): "[Anthropic Insights](https://www.anthropic.com/research/clio) (formerly named 'Clio'), the privacy-preserving tool our own teams use to analyze usage patterns across millions of Claude conversations." **Terminology note for the corpus:** the link target is still `/research/clio`, and `wiki/reports/programme-and-product-pages.md` records that the Economic Index hub page still calls the system "Clio". The rename is not propagated across Anthropic's own pages. `wiki/INDEX.md` carries the system's own publication as slug `clio-insights-2024-12`, whose file **did not exist on 2026-09-16** and is authoritative when written.

8. **How Anthropic Insights works — facets, clusters, runs, configurations, minimums** (*App. p.3*, quoted in full; **this is the fullest operational definition in the whole corpus of how Anthropic's privacy-preserving analysis produces a number**): "In brief: Anthropic Insights works by having Claude read a sample of conversations and answer a fixed set of researcher-written questions about each one—for example, 'what task is the user working on?' or 'does the assistant push back on the user at any point?' We call each question a facet. Answers to open-ended facets are then grouped by similarity into clusters, and Claude writes a short description of each group; answers to multiple-choice or numeric facets (e.g. 'how many self-corrections from Claude occur in this conversation?') are simply tallied. / Researchers can also specify facets computed programmatically (i.e., without Claude), like the number of human messages in the conversation. Any cluster containing fewer than a minimum number of conversations or accounts is dropped. A configuration is a partner's full set of facets and settings; a run applies it to an Anthropic Insights sample that computes the answers to a given set of facets. The outputs of an Anthropic Insights run are cluster descriptions and tallies and the corresponding number of conversations that fall under each category. Outputs are privacy-preserving and never contain conversations themselves. Our paper on Anthropic Insights describes the system in detail."

9. **The same mechanism restated on the web page, with the sensitivity to wording** (*WTL-B1*, quoted in full): "When using Anthropic Insights, a researcher writes a question such as, 'What type of guidance is this person asking for?' and Claude answers it for every conversation in the study. The answers are then aggregated into categories; researchers only see final categories and the percentage of conversations that fall under each one. Because we are relying on Claude's judgments, the tool is sensitive to a question's wording; a poorly phrased one can place conversations into categories that misrepresent them. Because no one can read the underlying conversations, these errors are hard to catch."

10. **Open-ended clusters, how they are built** (*App. p.12*, quoted in full): "Open-ended clusters are not discrete. Open-ended clusters are generated by embedding summary sentences generated by Claude, then clustering using K-means. As a result, variance in how Claude describes a behavior can split one topic across several clusters, and for smaller topics a single cluster can lump several distinct behaviors together. We also merge clusters that are individually too small to meet our aggregation thresholds, so some released clusters combine distinct activities. There is often no single best way to divide the data."

### A3. Privacy protections (appendix, quoted in full where the task requires it)

11. **The standing protections** (*App. p.5*, quoted in full): "Anthropic Insights was designed to protect user privacy. As described in our 2024 paper, no one, including Anthropic employees, sees the underlying conversations when using Anthropic Insights for research, only aggregated cluster names and descriptions. Clusters must contain a minimum number of distinct users and conversations, and they are stripped of identifying information. Furthermore, before we shared data with researchers, Anthropic staff manually reviewed every cluster name and description for privacy concerns."

12. **The layered safeguards specific to the pilot** (*App. p.4*, quoted in full): "Throughout the pilot, no external researcher ever had access to raw conversation data. All raw data and computation remain on Anthropic's servers; the research partners received only the aggregated, privacy-preserving outputs from Anthropic Insights. The processes below—validation runs, legal review, and manual output review—are additional safeguards layered on top of Anthropic Insights' design."

13. **The privacy threat model — its scope, its standards and its adversary** (*App. pp.6–7*, quoted in full): "Below is the privacy threat model we use to stress-test the Anthropic Insights data we share with outside researchers, updated since we gave it to the privacy red-teamers who evaluated this release. It is written with Anthropic Insights specifically in mind, but the same principles could apply to any AI provider sharing usage data for research. It does not cover Anthropic's handling of user data in general, our internal use of Anthropic Insights, or the security of our infrastructure. / The threat model borrows from two pieces of existing data protection guidance. The objective is for the data we release to be anonymous, and we assess each release against the three criteria in the European Data Protection Board's draft guidelines on anonymization: no record isolation (the data contains no combination of attributes that is unique to one person), no linkage (the data cannot be matched to information about the same person held elsewhere), and no inference (the data does not support any specific, meaningful conclusion about an individual). The adversary we model is based on the UK Information Commissioner's Office's 'motivated intruder': a competent person who wants to reidentify someone from the released data and will use any publicly available resource to do it. We also assume the adversary has access to the most capable AI models available."

14. **The four privacy harms in scope** (*App. p.7*, section A, quoted in full): "We treat the following outcomes as privacy harms, and assume an adversary may pursue any of them. / 1. Identity linkage. Linking a specific, identifiable person to their use of Claude, or to something they discussed with it. Example: showing that a particular named person used Claude to discuss their bankruptcy. / 2. Attribute disclosure. Learning a sensitive, non-public fact about an identifiable person, even where the data never states it directly. Example: inferring that a particular person has a serious medical condition. / 3. Small-group disclosure. Attributing a fact to members of a small, identifiable group. Example: learning something sensitive about the members of one recognizable local religious congregation. / 4. Organizational disclosure. Linking an identifiable organization to a non-public activity. This is a commercial confidentiality concern rather than a personal privacy one, but we treat it as in scope. Example: finding a recognizable company's unannounced product plans."

15. **What is explicitly *not* a privacy harm — including "unflattering aggregate findings"** (*App. pp.7–8*, quoted in full; **the middle bullet is the clearest statement in the corpus that Anthropic will not suppress a result because it is unflattering**): "Population-level inference about anonymous users. Group-level patterns are the subject of research on how people use AI. They become a privacy harm when the group is so narrow that membership exposes individuals, which is covered by the small-group disclosure case above. (Group privacy concerns should be addressed in study design and approval.) Keeping these sorts of large-scale patterns intact is critical for the effectiveness of the research, and undermining them seriously damages the utility of the data. Example: learning that some Claude users are job hunting. This is a fact about millions of people, and no individual can be shown to be among them, however sensitive the topic. / Unflattering aggregate findings. Discovering that Claude is used in ways Anthropic or others might prefer it were not is a research result, not a privacy harm. Example: a cluster reveals a large volume of Claude users seeking advice on how to cheat on their partners. / Skewing what a study finds. An adversary might want to influence the outcome of a third party's research about how people use Claude and plant conversations so that a topic looks larger than it is or so that a cluster appears at all. This is a research integrity concern rather than a privacy one, and section C explains why we consider the mechanism impractical."

16. **Suppression and the elimination attack, in Anthropic's own words** (*App. p.8*, quoted in full; **this is the only published statement of how Anthropic treats small-cell suppression in a released usage dataset, and it bears directly on every small-cell claim our own posts make**): "Recovering suppressed counts. We suppress any cluster or intersection between clusters that falls below our minimum user threshold. However, when a researcher's query sorts every conversation into a fixed set of categories, a suppressed category can sometimes be worked out by process of elimination. As in our prior public data releases, we do not treat this as a privacy harm in itself, only if it leads to one of the disclosures above. Example: a cluster of 100 conversations reported as 70% 'low' frustration and 29% 'medium' tells you the one remaining conversation was 'high.'"

17. **Method transparency: nothing about the method is secret** (*App. pp.8–9*, quoted in full): "We assume the adversary has access to all of the research data we publish and knows everything about how the research method works. For Anthropic Insights, that means they start with the full set of clusters, with our redactions applied and removed clusters absent. They know how the clustering works, including prompts substantially the same as those in our 2024 paper, and have everything published alongside the release, including the study's queries, its criteria for which conversations to include, which Claude products it sampled from, how many conversations it drew, and the length of the sampling window. We do not treat any part of the method or a study's configuration as secret."

18. **The sampling window is published only after the fact** (*App. p.9*, quoted in full; an operational constraint on any future applicant's design): "The first is the adversary who feeds the pipeline conversations of their own, planting them during the sampling window in the hope of pushing a target's conversations into a cluster small enough to reveal information about them. This is extremely difficult in practice. We publish the sampling window only after a study, so the adversary would be planting conversations without knowing what question the researcher is asking or when they should attack."

19. **What counts as a successful attack — the standard the data is held to** (*App. p.10*, section D, quoted in full): "An attack succeeds if it produces one of the harms in section A, using only the information in scope above. Notably, an attack does not need to narrow a cluster or intersection of clusters to a single person to be successful — getting down to a small set of real, identifiable candidates can be enough. How small that set has to be is not fixed and depends on the sensitivity of the finding. For instance, narrowing a cluster about people who like swimming to twenty real people is significantly less of a privacy concern than narrowing a cluster about people seeking advice on ending a romantic relationship to that same twenty."

20. **The planned tightening of the minimums** (*App. p.6*, quoted in full; the forward-looking commitment that most affects what a future applicant could see): "The most effective mitigation here is to increase the minimum number of users a cluster must contain. In future studies we plan to raise these minimums substantially, so that a tool would have to be in extremely wide use before it could surface this way, if at all. We also plan to change how cluster descriptions are generated so they are less likely to carry over distinctive phrasing, and to run the red-teamers' linking method ourselves on future data releases. In general, we plan to keep working with outside privacy red-teamers as this program develops."

21. **The misuse-disclosure rule** (*WTL-C*, quoted in full, and *App. pp.4–5*): *WTL-C*: "Some categories in our partners' Anthropic Insights outputs surfaced violations of our Acceptable Use Policy or Terms of Service—for instance a category of people seeking guidance on a prohibited activity. We think the public should know about misuse of our platform, so we shared most of these violations. The exceptions were categories that described *how* users got around our safeguards rather than *what* they attempted. Less than 5% of categories and conversations were affected in each study, and in each case we told researchers which clusters we had altered or removed and why. As a standard practice, when Anthropic Insights surfaces such violations, we share the aggregated data with our Safeguards team for their review. This is also an important process for our work with external researchers moving forward." *App. pp.4–5*: "We want to be transparent about misuse of Claude without encouraging it. ## Data and methods

What the pilot involved, what was released, and how access works — with references. The published numbers are in `## Claims`; this section is the procedure.

**What the pilot involved, step by step (App. pp.3–5, plus WTL-B1–B2).**
1. **Partner selection (February 2026).** Three groups chosen for "expertise in areas that we lacked", pre-existing relationship and tolerance for "the rough edges of a pilot" (definition 24). Not a competition; no call for proposals.
2. **Research primer.** Anthropic wrote a primer describing the programme's goals and "the technical details of Anthropic Insights necessary to design research the tool can support" (App. p.3). **The primer itself is not published** — it is described, not released.
3. **Collaboration agreement per partner** (definitions 3–4). Review rights limited to four named areas; publication right explicit, including inconvenient findings. **The agreements are not published either**; only their review clause is quoted.
4. **Proposal and configuration.** Each partner submitted research questions plus an Anthropic Insights configuration, then iterated with the Societal Impacts team: "Our input at this stage was technical, helping partners express their questions in a form Anthropic Insights could run. We assessed proposals for potential legal risk, but did not steer configurations based on whether the findings would reflect well on Anthropic." (App. p.4.)
5. **Validation run on WildChat.** Runs first executed on WildChat, a public corpus, "so the partners could validate their configurations and see real Anthropic Insights outputs before any Claude user data was involved" (App. p.4). Partners could revise once more afterwards. **This is the only place a partner could check Claude's answers against underlying conversations**, and the appendix says the transfer to Claude traffic failed in places (claim 20).
6. **Legal and privacy review of the finalised configuration**, "to ensure that they met the same privacy and legal standards we apply to our own research" (App. p.4).
7. **The production runs.** ~250K Claude.ai conversations each for Stanford and Oxford; ~250K Claude Code conversations for METR; each run a separate random sample from a fixed April–May 2026 window; Free, Pro and Max plans only; no Team, Enterprise or API data; Claude Code sampled from consumer users opted in to model-improvement data use; the METR window deliberately straddling a Claude model release (definition 30). Anthropic funded the runs and, where needed, partners' API credits for WildChat iteration.
8. **Manual review of every cluster** before release, "for substantive quality issues as well as whether sharing this data would compromise user privacy or safety" (App. p.4), with redaction rates published per partner (claim 17) and a reason given for every removal. Final say with the Societal Impacts team (definition 22). Misuse clusters go to the Safeguards team as standard practice (definition 21).
9. **~60 days of partner analysis**, then Anthropic's accuracy review of the write-ups, which produced "some corrections, concerning descriptions of Anthropic Insights' methodology" (definition 5).
10. **Third-party privacy audit.** The AI Security and Privacy Lab at Imperial College London, given the threat model and the clusters to be published, two weeks and $1,000 in Claude credits (definitions 13, 23; App. p.9). Result: no reidentification, no threat-model violation; one out-of-model pattern found (claims 18–19).

**What was released.** (a) This post; (b) the 12-page appendix, which is the methods document and contains the threat model and the interpretation guidance; (c) the Hugging Face dataset, four subsets, described by Anthropic as "the exact outputs each partner received" (definition 27), CC BY 4.0; (d) one partner writeup, SALT's, linked from both the post and the card at https://www.alphaxiv.org/abs/2608.human-ai-collaboration-at-scalev1 (HTTP 200 on 2026-09-16; **not fetched — it is an external researchers' output, not an Anthropic publication, and is outside this corpus**). **Not released:** the research primer, the collaboration agreements, the partners' full facet wordings and configurations for Oxford and METR (SALT's are said to be in their writeup), the two outstanding partner writeups, the redacted clusters themselves, and any cost or duration figure for the pilot.

**How access works, as documented.** The researcher never touches data. The researcher writes facets; Anthropic runs them; the researcher receives cluster names, descriptions, tallies, shares with 95% intervals and cross-facet tabulations, with sub-threshold cells suppressed (definitions 8, 9, 12, 29). Iteration on facet wording — which the appendix says is how Anthropic itself manages the tool's sensitivity, "iterating on the questions many times over weeks" (*WTL-B2*) — **is not available to external partners**, because "repeated privacy review before sharing each dataset would have made the study infeasible" (*WTL-B2*). The substitute was WildChat validation plus written interpretation guidance. Future access is by expression of interest only, with the single stated test in definition 25, and **both published form URLs were closed on 2026-09-16**.

This pilot's data is aggregated tabulations of classifier output over Claude traffic, published by Anthropic on *someone else's* facets. The difference that matters for a post is the **facet menu**: the Index releases carry Anthropic's constructs (task, occupation, collaboration pattern, primitive), while the released pilot files carry the partners' constructs and, for METR, session-level engineering measures. ## Limitations (verbatim)

The post and its appendix are unusually explicit about limits; the appendix's interpretation guidance is in effect a limitations section written for other people's use of the data. Items 1–7 are quotations. Item 8 is the wiki author's and is marked.

1. *WTL ¶1* — **the scaling limitation, which is the whole programme's binding constraint**: "However, all of this made the pilot slow for an AI lab's normal research speed and resource intensive to run. Both factors present a challenge to effectively scaling it."
2. *WTL-B1* — **wording sensitivity, and the reason errors are hard to catch**: "Because we are relying on Claude's judgments, the tool is sensitive to a question's wording; a poorly phrased one can place conversations into categories that misrepresent them. Because no one can read the underlying conversations, these errors are hard to catch."
3. *WTL-B2* — **the validation corpus does not match the target corpus**: "But WildChat skews toward casual and creative use, unlike Claude traffic, so some questions that performed well on WildChat produced misleading categories once applied to actual Claude conversations."
4. *App. pp.10–11* — **forced categorisation, and the explicit recommendation against harm claims**: "Forcing categorization may yield misleading clusters. When a facet requires Claude to make a judgment about every conversation, it will make one, even when the conversation gives it little to go on and the judgment is not warranted. If you ask for a critique of a conversation where Claude behaved appropriately, Claude will find a critique and state it plainly, no matter how small." … "This failure mode is especially common (and consequential) in facets that cluster concerning content in conversations. If a facet asks Claude to identify a problem in each conversation without giving it a way to say 'no issues,' the resulting clusters will overstate how often and how seriously things go wrong. The large majority of conversations may be ordinary, but they will still be assigned to a cluster describing a problem, however minor." … "We strongly recommend against drawing conclusions about harms from facets that force Claude to name an issue or behavior in every conversation. If a facet must produce an answer for every conversation, give it an explicit 'nothing notable' or 'n/a' option, or filter to conversations flagged by a separate classifier before clustering."
5. *App. p.11* — **editorialising, with the prompt named as one cause**: "Anthropic Insights cluster descriptions sometimes 'assume the worst' and overstate safety issues. This comes from two sources: the prompt and Claude's own behavior." … "Cluster names and descriptions are generated by prompts that encourage the model to describe safety issues clearly. The prompt instructs Claude that 'clusters that clearly describe harmful behavior are slightly preferred' and to not 'hesitate to identify and describe socially harmful or sensitive topics specifically' (see the original paper for the full prompt). These instructions are useful for surfacing real harms, but they bias the tool toward recall over precision, meaning it will flag more conversations as concerning, including some that are not." … "Minor or ambiguous behavior ends up described in strong evaluative language: legal guidance may become 'uncredentialed legal advice,' agreeing with the user may be described as 'uncritical sycophancy,' and a correct answer given without hedging may be labeled 'overconfidence.'"
6. *App. pp.11–12* — **the validity limit, and the restriction of the published accuracy figure**: "Cluster names and descriptions may not accurately describe all conversations within it. When we manually validated Anthropic Insights in the original paper, we found that roughly 3% of conversations were not clearly described by the cluster they were assigned to." … footnote 2: "Note that the accuracy figures in the original paper were measured on facets describing the topic of each conversation. Facets that ask Claude to judge model behavior or user emotional state were not validated in the original paper, so published accuracy numbers should not be cited in support of those clusters." … "While cluster names describing safety and behavioral issues can be a useful tool for understanding the kinds of issues that can occur in real-world conversations qualitatively, they cannot be used to make strong claims about the prevalence of different harms, and we strongly recommend against interpreting clusters as validated findings or as precise measurements of how often a behavior occurs."
7. *App. p.12* — **cluster sizes are not stable, and the recommended remedy**: "Cluster sizes should be interpreted with care. Because boundaries are rarely clean, differences in size between clusters can reflect the inherent randomness in LLM outputs rather than real differences in prevalence. Two Anthropic Insights runs on the same data will produce different clusterings. For understanding prevalence, we recommend using categorical classifiers, then using open-ended clusters to get qualitative insight into what comprises each category." … "Each conversation is only mapped to a single cluster, which means conversations that span multiple topics only receive a single description. As of May 2026, we estimate that roughly 10% of Claude.ai conversations span multiple topics."
8. *Card: Limitations*, quoted in full (the card's own list, which repeats some of the above and adds two): "Cluster names and descriptions are generated by Claude and should be read as interpretations of the underlying conversations, not as an objective measure of what those conversations contain. Do not treat clusters as validated findings or as precise measurements of how often a behavior occurs." / "Conversations were sampled from Free, Pro, and Max usage only. No Team, Enterprise, or API customer data was included. This population is not representative of our full user base." / "Claude Code conversations were sampled from consumer users who had opted in to letting Anthropic use their data to improve our models." / "Each study is a one-time snapshot of a fixed window in April-May 2026." / "One facet was removed entirely from Oxford's outputs because we strongly suspected a misphrased prompt caused misleading cluster descriptions." / "Anthropic Insights cannot distinguish attempts that our safeguards blocked from ones that succeeded; a cluster describing a harmful request often reflects what users asked for, not what Claude provided."
9. **Not a quotation — a limitation of the access route as observed, not a limitation the page states.** **Both expression-of-interest URLs published on the page were closed on 2026-09-16.** The standfirst's link (`…/forms/d/e/1FAIpQLScu…/viewform?usp=sharing&ouid=…`) and the "Looking forward" link (`…/forms/d/1PyyC-GU4Jra…/edit`) both redirect to `…/closedform` and return "The form Anthropic Insights External Research Collaboration: Expression of Interest is no longer accepting responses." The dataset card's link is the same form as the standfirst's and is equally closed. **Consequence for the programme: on the evidence available, there is no open route to Anthropic Insights access today, and no post or application may state that one exists.** The second URL is additionally an editor-side `/edit` link rather than a `/viewform` link — a publishing slip, recorded because it means the page never carried a working public link at that position.

## What it did not test

**This section is the wiki author's inference, not the text of any of the three documents.** It records (a) what the pilot demonstrably did not measure, (b) tensions between this document and the rest of the corpus, and (c) what a post of ours can do with it. Cross-references are by slug; each cross-referenced wiki file is authoritative for its own source, and files marked *(not yet written)* did not exist on 2026-09-16.

*What the pilot itself did not test*

1. **It did not test whether external access changes what gets found.** The post's warrant is that outsiders ask different questions (*LF ¶2*: "Our partners pursued research we would not have thought to design ourselves"), and its one testable instance is METR versus `claude-code-expertise-2026-06`. But the comparison is deferred ("something we'll follow"), METR's writeup is unpublished, and no side-by-side appears. **The central claim of the programme is untested by the programme.**
2. **It did not connect any partner finding to an Anthropic measure of the same thing.** *SALT-2*'s "nearly three-quarters of conversations, people set the direction while Claude assisted" is, on its face, adjacent to the Economic Index's augmentation share (per `/mnt/memory/standards/terminology.md`: augmentation = Task Iteration + Learning + Validation; automation = Directive + Feedback Loop). **The two are not the same construct** — SALT's is who set direction and whether output was adapted; Anthropic's is a five-pattern classification of the interaction — and **nobody reconciles them, in either direction.** A post that put the two numbers side by side would have to build the mapping itself, and say so. Note also that *SALT-1*'s "over half … delegating consequential tasks" uses "delegating" in a sense that is not the Index's automation share; our own naming convention (delegation = automation share) must not be quietly applied to it.
3. **It did not quantify the WildChat-to-Claude transfer failure.** The post says "some questions that performed well on WildChat produced misleading categories" (limitation 3) without saying how many, which, or by how much. The consequence is that no reader can bound how much of any partner finding is wording artefact. Given that the appendix separately says behaviour and emotional-state facets were never validated (limitation 6), **claims 8 and 9 rest on exactly the facet type the appendix says not to cite accuracy figures for** — the strongest internal tension in the document.
4. **It did not measure its own cost.** "Slow" and "resource intensive" are the only descriptors (claim 15). No duration, headcount, compute or dollar figure is published, so the feasibility question the post says it is weighing cannot be assessed from outside.
5. **It did not test the independence guarantee against a case.** The review rights were exercised once, on "descriptions of Anthropic Insights' methodology" (definition 5), which is the least contested category. No partner reports a finding that Anthropic resisted. **The guarantee is credible but unexercised.** Recorded also because one METR partner is listed as "Joel Becker (now at Anthropic)" in `ACK` — a partner researcher subsequently employed by the firm whose data he analysed, which no document discusses.
6. **It did not test representativeness of the sampled population in either direction.** The card states the frame is not representative (limitation 8) but publishes no comparison of the Free/Pro/Max consumer frame to Anthropic's full user base, to the Index's own samples, or to any population. The Claude Code subsample is additionally conditioned on opting in to model-improvement data use — a selection nobody characterises.
7. **It did not publish numeric aggregation minimums.** Definitions 8, 12, 16 and 20 all turn on "a minimum number", and none gives it. Since `metr_addendum` used "stricter" minimums than the rest (definition 24), **the released files are not mutually comparable on suppression**, and no reader can compute what a suppressed cell could have contained.

*Tensions with the rest of the corpus*

8. **The route this post opens is a Societal Impacts route, and the corpus's other access promises are economics routes that turn out to offer nothing privileged.** `wiki/reports/programme-and-product-pages.md` records that Economic Futures award recipients get "Consultation on analyzing Anthropic Economic Index data" and API credits but **no privileged data access**, and that the BFI partnership gives "Claude for Enterprise access", training and workshops, with "engage directly with the data" never specified. `wiki/reports/institute-agenda-2026-05.md` records that the agenda offers outsiders only publication and a fellowship. **So the single documented path to non-public usage data in the entire corpus runs through Societal Impacts, by invitation, and is currently closed.** That is a material fact for any application that promises analysis of non-public data, and it argues that our posts must stand entirely on public releases.
9. **The longitudinal promise and the threat model contradict each other, and this post is the document that makes the contradiction visible.** Item 6 of the open questions: longitudinal support would require revisiting the reidentification analysis; the Research Fund page promises "one of the first longitudinal datasets on AI's economic usage, diffusion, and impact". **A post could ask the answerable version: what can be said longitudinally from the public Economic Index releases alone, given their own changing taxonomies?**
10. **This is the first Anthropic document to state a small-cell disclosure policy in the terms our own posts need.** Definition 16 concedes the elimination attack on suppressed categories and says Anthropic does not treat it as a harm in itself, "As in our prior public data releases". Definition 19 sets the success standard at "a small set of real, identifiable candidates", not a single person. **Every geographic or small-cell claim our programme makes should be read against these two sentences**, and they are quotable Anthropic text for a limitations paragraph — which is worth more to us than any number in the post.
11. **The counterfactual-time construct now exists twice in Anthropic's published world, measured two different ways, and nobody has compared them.** `wiki/reports/productivity-gains-2025-11.md` records self-reported/model-estimated completion time without AI, aggregated by Hulten's theorem with OEWS wage-bill weights; METR here uses "Claude's guesses on how long tasks would have taken without AI" against observed elapsed time, by model generation, and validates those guesses against a prior developer study (claims 10–11). **The released `metr` subset appears to carry `time_without_ai` bands crossed with `model_version`** (steward question 2). If it does, a post could ask whether the two constructions agree — and either answer is a finding. **This is the most promising post-shaped gap in this document.**
12. **The rename is inconsistent across Anthropic's own pages, and this post is the one that makes the canonical statement.** "Anthropic Insights (formerly named 'Clio')" (definition 7) links to `/research/clio`; the Economic Index hub still says "Clio" (`wiki/reports/programme-and-product-pages.md`). Any post naming the system must say which name it is using and cite this page for the equivalence.
13. **Anthropic's own register here confirms the house naming rule, and can be cited for it.** The bullet headlines say AI — "People bring high-stakes work to AI more than expected", "How people feel when using AI is linked to how AI behaves", "More capable models may save users more time" — while the evidence sentences underneath say Claude: "over half of Claude conversations", "patterns … in Claude conversations", "Claude Code conversations". That is precisely the convention in `/mnt/memory/standards/terminology.md` (the question says AI; every finding says Claude), practised by Anthropic in this post. *(Wiki author's observation about register, not a claim of the post.)*

*Gaps our programme can exploit*

14. **The invitation in *WRL ¶2* is unanswered.** "We're excited about … what others will find now that the data is public." Nothing in `wiki/INDEX.md` analyses this dataset. Subject to the steward's answers, a post built on a public Economic Index release and layering the released `metr` or `stanford` cluster files — with the appendix's own interpretation guidance quoted as the limitations section — would be responding to an explicit Anthropic request, on data Anthropic released, using caveats Anthropic wrote. **The layering justification writes itself; the construct-mapping problem in item 2 is the work.**
15. **No one has audited the post's headline partner finding against the appendix's own warnings.** *SALT-1*'s "over half … consequential tasks" is compared only to unnamed "Prior research", and rests on a facet judging what a conversation was for. The appendix says forced categorisation inflates (limitation 4) and that behaviour-judging facets are unvalidated (limitation 6). **A referee-style re-derivation of that number from the released `stanford` file, against Anthropic's own stated cautions, is a legitimate and narrowly-scoped post** — and it is the kind of thing only an outsider will do.
16. **The corpus contains no measurement of how much of a published Anthropic number survives its own caveats.** This document is the first to publish, in Anthropic's voice, the full list of reasons a cluster share can mislead. Applying that list to Anthropic's own Economic Index releases — which use the same tool — is a contribution nobody in the corpus has made. *(It is also a claim that must be made carefully: the Index releases use categorical classifiers and published taxonomies, which limitation 7 explicitly recommends over open-ended clusters for prevalence. The honest version of this post is narrower than the tempting version.)*

# release_2026_06_26 — Economic Index report 6, "Cadences" (26 June 2026)

Sixth Economic Index release: monthly aggregates for **April and May 2026**, the first **wide-schema**
release, the first to carry **artifact** metrics, and the first whose accompanying report leans mostly on
data that is **not** in the public files (hourly/daily cadences, token counts, Claude Code comparisons,
survey). Accompanies <https://www.anthropic.com/research/economic-index-june-2026-report> (PDF and a
15-page appendix PDF, both on `cdn.sanity.io`; neither is in the Hugging Face folder).

Profiled 2026-09-16 at Hugging Face revision `2ea58ff75e4247d26810c37f10c179edc2466cac`
(`data/releases/INDEX.md`). Everything below was checked against the downloaded files; the commands are
in **Verification**. Fetch script: `data/fetch/release_2026_06_26.py`. Cache: `data/cache/release_2026_06_26/`
(gitignored), with a `.parquet` sibling for each CSV and `CHECKSUMS.txt`.


|---|---|---|---|

| `date_end` | string date | `2026-05-01`, `2026-06-01` | **exclusive** (documented); the two windows are calendar months and do not overlap |
| `geo_id` | string | `GLOBAL`; 121 ISO 3166-1 **alpha-3**; 652 ISO 3166-2 (whose prefix is ISO **alpha-2**) | see Grains |
| `geo_level` | string | `global`, `country`, `subregion` | exactly 3 |
| `category_name` | string | `overall`, `onet`, `request`, `soc_occupation` | exactly 4; **no crossed category** |

No nulls and no empty strings in any column of either file. Reading with `keep_default_na=False` is still
the house rule, but for **this** release no cell holds a token pandas would coerce (`NA`, `None`, `N/A`, …):

bite here. `node_external_id` is `-`, which pandas does not coerce.

## Grains

**Key.** `(date_start, geo_id, category_name, hierarchy_level, metric_id, node_external_id)` is unique:
0 duplicates in 1,636,573 rows (`claude_ai`) and 491,705 rows (`1p_api`). `geo_level` and `date_end` are
functionally determined by `geo_id` and `date_start`, so they are redundant in the key.
Substituting `node_name` for `node_external_id` produces **309 duplicate rows** in `claude_ai` — do not
key on the name.

**One "cell"** = `(date_start, geo_id, category_name, hierarchy_level, node_external_id)`; the metrics of a
cell are rows. In the wide-schema mental model, a cell is a row and `metric_id` is the column.

**Geography grains**

- `global` — one `geo_id`, `GLOBAL`. Both files.
- `country` — 121 ISO 3166-1 alpha-3 codes, all well formed, all length 3 (`claude_ai` only).
  114 in April, 121 in May; all 114 April countries recur in May (7 May-only additions).
- `subregion` — 652 ISO 3166-2 codes across **128 parent countries** (`claude_ai` only).
  536 in April, 652 in May; all 536 April subregions recur in May (116 May-only additions).
  Codes are 4, 5 or 6 characters (56 / 495 / 101): `AR-A`, `US-CA`, `AO-LUA`. **Not only US states** —
  US is the largest with 52, then JP 33, IN 27, MX 25, BR 24, CO 18, KR 17, DE/ES/IT 16 each.

**Month grain.** Two calendar months only. Both months are published for every metric family. There is
no week, day or hour grain anywhere in the public files, although the report's whole first chapter is
about hourly and daily patterns.

### Metric identities that hold inside the file

- The six collaboration **patterns** sum to 100 in every one of the 22,043 cells that publish them
  (max |sum − 100| = 0.03, pure rounding).
- The three **use-case** shares sum to 100 in all 22,061 cells (max deviation 0.01).
- The 32 **artifact** shares sum to 100 in all 22,059 cells that publish them, and all 32 are present
  whenever any is (max deviation 0.09).
- The two collaboration **buckets** sum to 100 wherever both are published (21,809 cells).
- **`collaboration_bucket_automation_pct` = (directive + feedback_loop) ÷ (directive + feedback_loop +
  task_iteration + learning + validation) × 100** — i.e. renormalised over the five *classified* patterns,
  excluding `none`. Over all 21,809 cells: mean |error| 0.0035, max 0.124, 21,802 within 0.05. The two
  rival specifications fail: dividing by all six patterns gives mean |error| 2.02 (max 98.9), and taking
  directive + feedback_loop without renormalisation gives mean |error| 2.02. **The skill's formula is
  correct for this release and is confirmed to rounding.**

## Thresholds

**The public files apply the thresholds; you cannot.** `data_documentation.md`: "A cell is only published
if it meets both the aggregation thresholds and the geography sample floor for the given row… A missing
row means the cell was not published, not necessarily that the value is zero." Neither the threshold
values nor the sample floor are stated.

- **There is no count metric of any kind.** All 53 metrics are percentages, indices or means. There is no
  `usage_count`, no conversation count, no denominator, no sample size. Confirmed: 53 metric ids, none
  matching `count|n_|total|obs`. The skill's "June 2026 files carry no per-country usage counts; treat
  them as pre-filtered" is **verified**.
- Consequence: the standard convention of applying 200 conversations per country and 100 per US state
  yourself (constants in Anthropic's 2025-09-15 code) **cannot be applied to this release at all**, and
  cannot be checked. The published set is the filtered set. Any inclusion rule must be built from what is
  observable — e.g. "country publishes `usage_pct` in both months", "at least N nodes present at this
  category and level" — and stated as a proxy.
- **There is no `not_classified` node and no residual node anywhere.** Where a coarse `pct` fails to reach
  100, the shortfall mixes unclassified conversations with suppressed cells and the two are not
  separable. The shortfall is large and systematic (see below).
- **Suppression is the dominant feature of the fine grains.** `pct` sums, median over unit-months:

| geo_level | `onet` L0/L1/L2/L3 | `request` L0/L1/L2 | `soc` L0/L1 |
|---|---|---|---|
| global | 91.4 / 95.1 / 95.8 / 96.7 | 96.4 / 96.6 / 96.6 | 96.4 / 96.7 |
| country | 36.9 / 66.2 / 89.1 / 96.4 | 55.4 / 86.1 / 96.5 | 77.4 / 96.6 |
| subregion | 16.7 / 40.7 / 77.4 / 94.0 | 26.8 / 61.9 / 95.1 | 49.9 / 94.7 |

  At the worst, a country-month accounts for 1.90% of itself at `onet` L0 and a subregion-month 1.51%.
  **Only the top of each ladder is usable as a mix**: at `onet` L3, `request` L2 and `soc` L1 the sums are
  94–97% everywhere, and the ~3–5% missing at global level is unclassified conversation, not suppression.
- Nodes present per unit-month, median (of the release's node universe): country `request` L0 78 of 1,012;
  country `onet` L0 49 of 2,861; country `soc` L0 98 of 718; subregion `request` L0 20 of 1,012;
  subregion `onet` L0 10 of 2,861. **The comparable node set shrinks to nothing at leaf level.** This is
  the June-2026 form of the skill's "per-country level-0 request clusters present: median 42 of 588".
- **Publication is ragged even inside the "all 51 metrics" country blocks.** Of the 12,319
  country × top-of-ladder cells, 9,557 publish all 51, **2,568 publish `pct` alone**, and 194 publish
  between 41 and 50. The thing dropped first is the collaboration pair (`bucket_automation`,
  `bucket_augmentation`: 234 cells lack them although the patterns are published — in those cells the
  five classified patterns sum to a median of only 58%, so the bucket was suppressed as too thin), then
  `human_only_time_mean` and `human_with_ai_time_mean`, then the six patterns. **Never assume a metric
  exists for a cell because it exists for a sibling node.**
- At `subregion`/`overall`, 102 of 1,188 unit-months publish 52 metrics (the 51 US states + DC × 2),
  1,082 publish 51 (no AUI), and 4 publish 50 (**no `usage_pct` either**: `HT-OU` in both months,
  `CG-16` and `MR-13` in May).

**AI Usage Index — the specification that reproduces.** The report and documentation define the AUI as
usage share ÷ working-age population share. The files publish no population. Using
`release_2025_09_15/data/intermediate/working_age_pop_2024_us_state.csv` (51 rows) and
`…/working_age_pop_2024_country.csv` (194 rows, 2024 vintage):

- **US states: reproduces.** `AUI = (usage_pct ÷ Σ usage_pct over the published states) ÷ (pop ÷ Σ pop over
  the same states)`, over the 51 states + DC, excluding `US-PR`. Mean |error| **0.0045** (April) and
  **0.0048** (May); **all 51 within 0.05** in both months; correlation 0.99994. Σ `usage_pct` = 100.00, so
  the renormalisation is a no-op and the simpler `usage_pct ÷ pop_share` gives the same answer.
  Merge audit: 104 state-months in, 102 matched, 2 unmatched (`US-PR`, which has no AUI anyway).
- **Countries: the form reproduces, the level does not.** The same specification, with both sums taken over
  the **published countries of that month**, gives mean |error| **0.0333** (April) and **0.0354** (May) over
  all countries and **0.0067 / 0.0070** (max 0.048) over the 36 countries with `usage_pct ≥ 0.5`. The large
  residuals are all tiny countries where two-decimal rounding of `usage_pct` dominates (Iceland,
  `usage_pct` 0.02, error 0.88). Merge audit: 235 country-months in, 235 matched to `usage_pct`, 235
  matched to the population file, 0 unmatched; 73 population-file countries are not in the June file.
  Two wrong specifications, for the record: population share over the 194-country file gives a *uniform*
  ratio of 0.899 (std 0.0056 across 36 countries) — the functional form is right and only the denominator
  universe is wrong; population share over published countries without renormalising `usage_pct` gives a
  uniform ratio of 0.924. The implied global working-age denominator is **4.46e9** (April) and **4.23e9**
  (May), 17% and 11% above the 2024 file's 194-country total of 3.80e9, consistent with Anthropic using a
  2026 UN WPP vintage over a wider country universe (report footnote 19 names World Bank WDI 2024, UN WPP
  2024 and IMF WEO 2025). **Independent confirmation of the form**: the population-weighted mean of the
  published country AUI, weighted by 2024 working-age population, is **0.9996** (April) and **0.9993**
  (May) — the identity that the renormalised specification implies.
  **Practical rule: country AUI ranks, ratios and month-to-month changes reproduce exactly; absolute
  country AUI levels cannot be rebuilt from public data to better than ~1%.**
- This **refines the skill**. The skill says the usage denominator is "usage over thresholded countries
  PLUS `not_classified`" and the population denominator is "over thresholded countries only". For June
  2026 there is no `not_classified` row and `usage_pct` is already taken over the global total (it sums to

## Cuts that do not exist

Stated plainly. Each of these is absent from the release, and for the ones the report discusses there is
no substitute in the public data.

1. **No cross of any two categories, at any grain.** `category_name` has four values, none of them a
   cross. In particular: **no request × occupation cross at any grain** (the skill's claim, **verified**);
   no onet × collaboration; no request × collaboration (both of which existed at global level in
   2025-09-15). Nearest substitute: compare marginals within a cell, or use the 2025-09-15 global
   `onet_task::collaboration` and `request::collaboration` facets on an August-2025 window with a
   different taxonomy — a different wave and not comparable.
2. **No cross of a metric with a metric.** The metrics of a cell are independent marginals. So there is no

   collaboration × use case. **Cost:** every headline in report Chapter 2 beyond Figure 2.1 is

## Traps

1. **`hierarchy_level` 0 is the leaf, 3 is the broadest** — the opposite of the intuition, and the
   opposite of the 2025-09-15 `level` semantics for request clusters. Every "use the top of the ladder"
   rule therefore reads `onet` **3**, `request` **2**, `soc_occupation` **1**, `overall` **0**.
2. **`hierarchy_level` is a string in the CSV** ("0".."3") although documented as int. Sorting it as text
   happens to be correct for one digit; comparing it to an integer silently matches nothing.
3. **`node_name` is not a key.** 309 rows in `claude_ai` duplicate on
   `(date, geo, category, level, metric, node_name)`; three `onet` L0 task statements appear under two
   Task IDs each. Always key on `node_external_id`.
4. **`geo_id` mixes two ISO code systems.** Countries are alpha-3 (`USA`), subregion prefixes are alpha-2
   (`US-CA`). `release_2025_09_15/data/intermediate/working_age_pop_2024_country.csv` carries both
   (`iso_alpha_3`, `country_code`) and is the cheapest bridge, covering 194 countries.
5. **`US-PR` is a subregion of `US` *and* `PRI` is a country.** Puerto Rico is therefore counted twice in
   any union of country and subregion rows, and it is outside the US `usage_pct` base (the 51 states + DC
   sum to 100.00 without it). Filter it explicitly in state analyses; the 51-unit set (50 states + DC) is
   the one Anthropic uses, since it is exactly the set carrying `usage_per_capita_index`.
6. **`GLOBAL` identity rows.** `usage_pct` = 100.00 and `usage_per_capita_index` = 1.00 at `GLOBAL` in both
   files. Any mean or regression that pools `geo_level` values will ingest them.
7. **A metric's presence for one node says nothing about its presence for a sibling.** 2,568 of 12,319
   country top-of-ladder cells publish `pct` alone; 234 publish the collaboration patterns but not the
   buckets. Pivot to wide and check `notna()` per cell; never `fillna(0)`.
8. **`value` is pre-rounded to two decimals, and that is the binding constraint on every reconstruction.**
   Ratios of small numbers are unusable: Iceland's `usage_pct` of 0.02 carries ±25% relative error, which
   is exactly why its AUI residual is 0.88 while the 36 large countries sit at 0.007.
9. **Units differ by metric.** `human_with_ai_time_mean` is minutes and exceeds 100 in 195 rows;
   `human_only_time_mean` is hours. A blanket "clip to [0,100]" corrupts them.
10. **The two months are not poolable by volume.** With no counts, the only defensible pooled figure is the
    unweighted mean of the two months, and it must be labelled as such. Anthropic's own Chapter 2 window
    (10 April – 10 June) matches neither month, which is the source of the one 1.0 pp discrepancy found.
11. **The taxonomy universe changes between the two months.** Global `onet` L0 publishes 2,410 nodes in
    April and 2,713 in May (union 2,861); `request` L0 1,001 → 1,007 (union 1,012). A month-over-month
    mix comparison must be restricted to the intersection or it will attribute entry and exit to change.
12. **The `claude_ai` and `1p_api` node universes differ**, including at the top: `onet` L3 has 35 nodes in
    one file and 37 in the other. Cross-surface comparisons must intersect first
    (`onet` L0 shares only 1,969 of 2,861 / 2,427).
13. **O\*NET Task IDs are from O\*NET 30.2** (appendix) and only **2,258 of 2,861** join to
    `release_2025_09_15/data/intermediate/onet_task_statements.csv` (`Task ID`), a 78.9% match. Likewise
    `soc_occupation` L0 matches only 543 of 718 `O*NET-SOC Code` values in that file, whose universe is
    occupations with task statements; use a SOC structure file (`release_2025_09_15/data/intermediate/
    soc_structure.csv`) for the occupation join. **O\*NET L1/L2/L3 element IDs join to nothing in the
    repository** — the DWA/IWA/GWA reference must come from O\*NET itself.
14. **The `NA`-is-Namibia rule does not bite here** (no bare `NA` token in any column of either file), but
    `keep_default_na=False` is still the right default and costs nothing; `node_external_id` for
    `overall` is the literal `-`, which pandas leaves alone.
15. **"Occupation" is inferred from the task, not from the user** — carried over from earlier waves and
    made explicit by the report appendix's Example 7, where "which Rust library is best for NLP?" maps to
    a **sales** occupation because the assistant is "recommending products". Treat `soc_occupation` as a
    task taxonomy wearing occupation labels.
16. **Reading the 219 MB CSV with inferred dtypes costs ~8× the Parquet.** Use
    `data/fetch/release_2026_06_26.py`'s Parquet output; the full `claude_ai` frame is 7.1 MB on disk and
    loads in about a second.

## Schema

`task_pct_v1.csv` / `task_pct_v2.csv` — 2 columns:
`task_name` (object; lower-cased, stripped O\*NET task text, 99.97% end in `.`; e.g.
`act as advisers to student organizations.`), `pct` (float64, percent; e.g. `0.006775156024025746`).

`automation_vs_augmentation_v1.csv` / `_v2.csv` — 2 columns: `interaction_type` (object; exactly
`directive`, `feedback loop`, `learning`, `none`, `task iteration`, `validation` — spaces, not
underscores), `pct` (float64, percent).

`automation_vs_augmentation_by_task.csv` — 7 columns: `task_name` (object, joins `task_pct_v2`),
then `feedback_loop`, `directive`, `task_iteration`, `validation`, `learning`, `filtered`
(all float64, ratios in [0,1], **underscored** names, no blanks). Column order in the file is
that order; the README lists them in a different order.

`task_thinking_fractions.csv` — 2 columns: `task_name` (object, exactly the `task_pct_v2` set),
`thinking_fraction` (**object** on a default read: 2,950 of 3,365 cells are empty; non-empty
values are floats in [0.0077485056, 0.41095892]).

`onet_task_statements.csv` — 8 columns (the release README documents only three of them):
`O*NET-SOC Code` (object, e.g. `11-1011.00`), `Title` (object), `Task ID` (int64),
`Task` (object, original capitalisation), `Task Type` (object: `Core` 13,487, `Supplemental`
5,385, blank 658), `Incumbents Responding` (object; blank for the same 658 rows),
`Date` (object, `MM/YYYY`, 17 distinct values `03/2003`…`02/2011`… `07/2014`),
`Domain Source` (object: `Incumbent` 14,511, `Occupational Expert` 4,361, `Analyst` 658).

`SOC_Structure.csv` — 6 columns: `Major Group`, `Minor Group`, `Broad Occupation`,
`Detailed Occupation`, `Detailed O*NET-SOC`, `SOC or O*NET-SOC 2019 Title`. Exactly one of the
five code columns is non-blank on every row (verified), so the file is a ragged hierarchy, not a
lookup: 23 major-group rows, 98 minor, 459 broad, 867 detailed, 149 detailed O\*NET-SOC.

`cluster_level_data/cluster_level_dataset.tsv` — 16 columns, tab-separated:
`cluster_name_0`, `cluster_description_0`, `cluster_name_1`, `cluster_description_1`,
`cluster_name_2`, `cluster_description_2` (all object; some descriptions start with a leading
space), `percent_records` (float64), `percent_users` (float64), `onet_task` (object, **verbatim**
O\*NET task text, 11 blanks), `collaboration:directive_ratio` (float64),
`collaboration:feedback loop_ratio`, `collaboration:learning_ratio`, `collaboration:none_ratio`,
`collaboration:task iteration_ratio`, `collaboration:validation_ratio`, `has_thinking_ratio`
(all object on a default read because of blanks; **the column names contain a colon and a
space**).

## Grains

- `task_pct_v{1,2}.csv`: one row per **normalised O\*NET task name plus one pseudo-task `none`**.
  `task_name` is unique (0 duplicates in either file).
- `automation_vs_augmentation_v{1,2}.csv`: one row per interaction type; 6 rows, unique.
- `automation_vs_augmentation_by_task.csv`: one row per v2 task **excluding `none`**; 3,364 rows,
  `task_name` unique.
- `task_thinking_fractions.csv`: one row per v2 task **including `none`**; 3,365 rows, unique.
- `onet_task_statements.csv`: one row per (`O*NET-SOC Code`, `Task ID`); 19,530 rows, that pair
  unique, `Task ID` alone also unique. 974 occupation codes, 18,429 distinct task statements
  (18,428 after lower-casing), so a task statement can belong to several occupations.
- `SOC_Structure.csv`: one row per SOC code at one of five levels; 1,596 rows. Titles are **not**
  unique (263 duplicated titles).
- `cluster_level_dataset.tsv`: one row per **level-0 cluster**; 630 rows, `cluster_name_0`
  unique. The hierarchy is a strict tree: every level-0 name has exactly one level-1 parent and
  every level-1 name exactly one level-2 parent (max parents = 1, 0 violations).
- **Everything in this release is global.** No file has a geography, date, model, product or
  platform column.

## Facets or categories

- **Tasks**: O\*NET task statements, lower-cased and stripped in the usage files, verbatim in
  `onet_task_statements.csv` and in the cluster file's `onet_task`. Join key is the lower-cased,
  stripped `Task`.
- **Occupations**: not a column anywhere in the usage files. They are *derived* by joining task
  text to `onet_task_statements.csv` (`Title`, `O*NET-SOC Code`) and to `SOC_Structure.csv` on the
  first two digits of the O\*NET-SOC code (the notebook's `merge_onet_soc_data`).
- **The five collaboration patterns plus `none`**: automation = `directive`, `feedback loop`;
  augmentation = `validation`, `task iteration`, `learning`; `none` is a sixth row and is dropped
  before the automation/augmentation split. The per-task file replaces `none` with `filtered`
  (privacy/safety-excluded residual) and uses underscored names.
- **`filtered`** (per-task file only): residual so that each row sums to exactly 1.0.
- **Cluster hierarchy** (bottom-up Clio taxonomy, names only, no ids): 630 level-0 →
  145 level-1 → 30 level-2. Level-1 groups hold 1–16 level-0 clusters (median 3); level-2 groups
  hold 2–46. 7 rows have `cluster_name_1 == cluster_name_2` and 5 have
  `cluster_name_0 == cluster_name_1` (single-child chains), so level counts are not disjoint by
  name. Largest level-2 clusters by summed `percent_records`: Help create and improve
  professional documents and communications 7.27, Develop and troubleshoot software applications
  with specific features 7.25, Develop data analysis and visualization systems 6.40.
- **"Thinking fractions"**: the share of a task's conversations that used Claude 3.7 Sonnet's
  extended-thinking mode (`task_thinking_fractions.csv`), and the cluster-level equivalent
  `has_thinking_ratio`. Binary usage flag aggregated to a ratio; no token or duration measure.
- **Versions**: `v1` = first-report window (Dec 2024–Jan 2025, Claude 3.5 Sonnet era),
  `v2` = second-report window (11 days after the 3.7 Sonnet launch, Feb–Mar 2025). The window
  dates exist only in the blog post, not in the files.

## Thresholds

- **No usage threshold, suppression rule or minimum-observation constant is stated anywhere in
  this release**, and no geography exists for the 200-per-country / 100-per-state rules of later
  waves to apply to.
- **Privacy bucketing (documented, cluster file only):** `percent_records` and `percent_users`
  were sorted, split into 100 buckets, and each value replaced by its bucket average. Verified:
  `percent_records` has exactly **100 distinct values** across 630 rows (`percent_users`: 99),
  with up to 7 clusters sharing a value. Ranks are approximately preserved; precision is not.
- **Undocumented cell suppression (cluster file):** blanks in the collaboration and thinking
  columns. Counts: `none` 99, `validation` 75, `feedback loop` 47, `task iteration` 12,
  `learning` 5, `directive` 0, `has_thinking_ratio` 29. 178 of 630 rows have at least one blank;
  none has all six blank. Rows with a blank sum to 0.945428–0.998953 instead of 1, so a blank is
  a small suppressed share, not a zero and not missing data. Smallest published values are
  0.0054865 (collaboration) and 0.0061977 (thinking), consistent with a count-based floor; **the
  rule is not published and cannot be recovered from the file.**
- **`filtered`** in `automation_vs_augmentation_by_task.csv` is the analogous residual at task
  level and is published as a number rather than suppressed. `filtered == 1.0` for 1,066 of
  3,364 tasks (31.7%), i.e. a third of tasks carry no usable collaboration split.
- **Blank `thinking_fraction`** (2,950 of 3,365 tasks, 87.67%) covers tasks holding 24.86% of v2
  usage. Anthropic's own published figure treats these as **zero** (see Traps).
- Figure-level thresholds used by the report and its code, not by the files: occupational
  categories and occupations are shown only at **≥0.5% prevalence** (`min_prevalence=0.5`,
  `pct_occ_scaled >= 0.5`): 17 of 22 SOC major groups, 35 of 749 occupations.

## Cuts that do not exist

- **No geography of any kind.** No country, region, state, city or language column in any file.
  Anything geographic must wait for `release_2025_09_15`.
- **No dates, no time series inside the release.** No `date_start`/`date_end`, no month, no day.
  The only "time" is the v1/v2 contrast, and the two windows are named only in the blog post.
- **No counts.** No conversation, user, message or token counts anywhere — only percentages and
  ratios. The "1 million conversations" denominator is not published, so no standard error,
  confidence interval or significance test on any share is possible from these files.
- **No cluster-level v1.** The bottom-up taxonomy exists for v2 only, so no cluster-level change

- **No thinking × collaboration cross** at any grain: the per-task thinking file has no pattern

- **No occupation-level or SOC-level file.** Occupations and major groups exist only as a

- **No cluster → occupation mapping** other than the single `onet_task` text per cluster
  (11 clusters have none).
- **No model, product, plan or platform split**: no Claude 3.7 vs 3.5, no Free vs Pro, no API, no

  post's words only.)
- **No employment or wage denominators in this release.** `bls_employment_may_2023.csv` and

- **No `data_documentation.md`** (only `README.md`), and no `not_classified` label — this

- **No user-level anything**: `percent_users` exists at cluster level only and is bucketed.

## Traps

1. **`task_pct_*` contains a pseudo-task `none`** (v1 0.48%, v2 1.78%) that matches no O\*NET
   statement. The notebook drops it implicitly by an inner/left join and renormalising; a naive
   "share of tasks" that keeps it will be 1.8% low in v2 and 0.5% low in v1, and the v1→v2
   comparison inherits the difference.
2. **v1 and v2 interaction files are not on the same base.** `automation_vs_augmentation_v1.csv`
   sums to **84.2092**, `_v2.csv` to **99.9965**. Dividing v1's directive+feedback loop by 100
   gives 34.60% automation; the published, comparable figure is 42.55% (÷ 81.3079, the sum after
   dropping `none`). Always drop `none` and renormalise before comparing versions — this is what
   notebook cell 19 does. The v1 shortfall is the occupational-relevance filter that the second
   report dropped (stated in the post's "Additional methodological details").
3. **Blank `thinking_fraction` must be treated as 0, not dropped.** Anthropic's published
   occupation figure is reproduced to 0.02 pp mean error only with blank = 0 and the full task
   set in the denominator; dropping blanks gives 0.31 pp mean error, up to 1.14 pp, and changes
   the ranking. (Earlier digests in `reference/` say blank "means not computed, not zero" — true
   about provenance, wrong as a recipe for the published number.)
4. **Task → occupation is many-to-many.** 272 task statements belong to up to 34 occupations. The
   released convention is: divide the task's `pct` by the number of distinct occupations holding
   it (`n_occurrences`), then renormalise the total to 100 (`pct_occ_scaled`). Any other choice
   (duplicate the full `pct`, or drop duplicates) will not reproduce the published figures.
5. **The occupation join is on lower-cased, stripped `Task`.** `task_pct_*` is lower-cased but
   the cluster file's `onet_task` and `onet_task_statements.Task` are not.
6. **Running the notebook in the release folder overwrites released PNGs.** Cells 17–19 call
   `fig.savefig('normalized_automation_by_category.png')`,
   `'automation_augmentation_by_occupation.png'` and `'automation_augmentation_comparison.png'` —
   exactly the three PNG file names shipped in the folder. Run it in a scratch directory with
   symlinks to the CSVs only (what `/tmp/run_nb.py` did here).
7. **`cluster_level_example_analysis.ipynb` cell 2 calls `display()`**, an IPython builtin, so it
   fails outside a notebook kernel (`NameError`). Cells 4, 6, 7 run under plain Python. The
   notebook produces no published number.
8. **Both notebooks declare `kernelspec: Coconut` / `language: coconut`.** The code is ordinary
   Python 3 + pandas/matplotlib/seaborn; ignore the kernel metadata.
9. **Cluster column names contain a colon and a space** (`collaboration:feedback loop_ratio`), and
   five of the seven ratio columns load as `object` because of blanks. Convert explicitly.
10. **Cluster collaboration ratios exclude a `filtered` residual**, unlike the per-task file, and
    rows with all six values present sum to 0.998963–1.0 — so they are *approximately*
    normalised; do not assume exactly 1.
11. **`percent_records` / `percent_users` are bucket averages** (100 buckets): up to 7 clusters
    share an identical value, so ties are artefacts. Do not compute concentration statistics
    (HHI, Gini) or rank-based tests that assume distinct values.
12. **`filtered` swamps rare tasks**: 1,066 of 3,364 tasks are 100% filtered and 1,276 are over
    50%. Unweighted means over tasks are dominated by them (unweighted mean `filtered` 0.454 vs
    usage-weighted 0.082). Weight by `pct` and renormalise out `filtered`.
13. **`SOC_Structure.csv` is a ragged hierarchy**, one code column per row and 263 duplicated
    titles; the released recipe is `dropna(subset=['Major Group'])` then join on the first two
    characters of the O\*NET-SOC code. Joining on title will silently multiply rows.
14. **The v1/v2 task lists are not a panel** (733 v1-only, 584 v2-only tasks), so "change in a
    task's share" is defined for 2,781 tasks only; the entry/exit is not random (rare tasks).
15. **`NA`-as-Namibia does not bite here** (no cell in any file equals a pandas default-NA token
    other than the empty string), but blank-versus-zero does; read with `keep_default_na=False`
    and decide blanks explicitly.
16. Occupation in this release is **inferred from the task text**, never from the user, and the
    post itself warns the O\*NET wording may misdescribe usage (its "fine artists" example).

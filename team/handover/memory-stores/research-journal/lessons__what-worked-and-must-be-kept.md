## Shared working tree and git (keywords: git, shared tree, pull --rebase, stash, worktree, concurrent threads)
Added 2026-09-16 (session 1.2). All child threads in a session write to the same checkout. `git pull --rebase` refuses while any thread has unstaged edits, and `git stash` would silently carry away other threads' in-progress files. Pattern that works: `git add <own paths only>` → commit → `git fetch origin main` → if the tree is dirty, push from a temporary worktree (`git worktree add /tmp/x origin/main && cd /tmp/x && git cherry-pick <sha> && git push origin HEAD:main`). Never `git reset --hard` or `stash` in the shared tree. Put this in every specialist's task text.

## Dead-thread drafts are not evidence (keywords: dead thread, unverified draft, billing failure, re-verify)
Added 2026-09-16 (session 1.2). Six threads died on a billing error leaving uncommitted drafts. Fresh owner threads that re-verified them against source found 4–7 factual errors in each (word/repetition counts, page numbers, a wrong "no such cut" claim, a wrong decimal). Rule: a draft from a dead thread is input to a fresh owner thread that re-fetches the source and re-verifies every quote and number before committing; the director never commits it.

## Steward confirmation before the referee, one amendment pass per brief (keywords: feasibility note, column level, amendment pass, Kish, effective N, session 1.4)
Added 2026-09-16 (session 1.4). Running the steward's column-level confirmation on each brief before the referee sweep caught material errors in all five batch-1 briefs (wrong wage join key, wrong success construct, undeliverable equivalence margins, a missing facet with 3× the coverage, an untestable hypothesis signature). Sequence that works: lead brief → steward note → lead's ONE §8 amendment pass (via the same lead thread; no new thread) → editor note (can run parallel to the steward) → referee sweep on the amended brief → at most one design pass on a BLOCK. Kish effective N under usage or count weights collapsed power in every design; unweighted primary with weighted robustness is now the default rule.

## Billing stops and archived threads (keywords: billing error, usage limit, archive, duplicate thread, dead-thread commit, worktree push)
Added 2026-09-16 (session 1.4). Four billing stops in one session. What held up: (1) verdict-first-then-room-note commit order, so a dying referee still landed its verdict; (2) fresh threads instructed to write whole files from `git show origin/main:<path>` so dead partial diffs never survived; (3) writing the halt note and journal at the FIRST failure notification. What went wrong: (a) "all idle threads archived" did not include threads mid-turn, so a respawned duplicate had to be stood down — always list_agents and re-fetch origin/main before respawning; (b) a thread that committed locally but died before pushing left unpushed commits on a diverged local main — treat them as dead drafts, hand them to the fresh owner as a checklist, never push them as director. Budget: a referee brief-stage sweep with re-derivations is the most expensive single turn; sequence sweeps by the post the human will approve first.
